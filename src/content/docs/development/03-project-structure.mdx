> Code is grouped by why it exists, not by what it is.

Every Stratastax repository looks the same from the outside, and every service from the inside.

---

# 1. Every Repository

```text
.
├── .github/workflows/      callers of the shared workflows (build, release, docs)
├── .sdkmanrc               the JDK, used locally (`sdk env`) and in CI
├── gradle.properties       version, stratastax.repository, stratastax.displayName
├── settings.gradle.kts     the dev.buijs.stratastax.settings plugin
├── stratastax.versions.toml  versions of the Stratastax modules it uses (optional)
├── CHANGELOG.md            Keep a Changelog; [Unreleased] becomes the release
├── LICENSE
└── README.md               what it is, how to use it, related projects, documentation
```

- The build uses the [convention plugins](/technical/components/gradle/): no repository carries
  its own copy of Kotlin, publishing, formatting or coverage settings.
- Work happens on `feature/*` branches into `develop`; `main` holds what is released. A release
  is a tag on `develop` followed by a release pull request to `main`.

---

# 2. A Library

A library is a Gradle multi-project, one module per concern, with a framework-free core and thin
integrations:

```text
stratastax-http/
├── problem-core/           no framework
├── problem-persistence/    resolvers for persistence errors
├── idempotency-core/
├── idempotency-reactive/   the jOOQ store
└── quarkus-http/           the Quarkus integration
```

Inside a module, packages separate what callers use (`api`), what they implement or configure
(`spi`) and the module's own internals (`internal`, invisible outside the module). Where a library
checks its public API with an ABI dump (persistence does), an accidental change fails the build.

# 3. A Service

```text
src/main/kotlin/dev/buijs/stratastax/engine/
├── features/
│   ├── games/
│   │   ├── Game.kt              entity (annotated) + its id and value types
│   │   ├── GameRules.kt         invariants as pure functions
│   │   ├── GameService.kt       implements the generated delegate
│   │   └── GameClient.kt        a port to another service, when needed
│   ├── matches/
│   │   ├── Match.kt
│   │   ├── MatchRules.kt
│   │   ├── MatchProblem.kt      the feature's exceptions
│   │   └── MatchService.kt
│   └── shared/                  only what several features truly share
└── infrastructure/              application-wide wiring
src/main/resources/application.yaml
src/test/kotlin/dev/buijs/stratastax/engine/
├── api/v1/                      capability tests over the REST API
├── features/<feature>/          rule, service and SQL tests
└── testdata/                    seeded actors, requests, scenarios
build/stratastax/                generated by codegen (never edited, never committed)
```

## Rules

- **One package per feature**, named after the capability (`matches`, `matchedits`), never after a
  layer (`services`, `repositories`).
- **Everything a feature owns lives in its package.** A feature uses another feature through its
  service or a port, never through its tables.
- **No hand-written REST, mapping or repository code** where the generator can produce it. If it
  cannot, improve the generator or the annotations first.
- **Migrations are not in the service.** They are in the contract; the service consumes the
  schema artifact.
- **Generated code is not edited.** It is rebuilt on every build and excluded from coverage.

# 4. A Flutter App

```text
stx.yaml                   backends, contracts, tokens, i18n, security
stx.lock                   the pinned remote specs and tokens (committed)
stx.tokens.yaml            the app's own tokens, on the brand layer
i18n/<locale>.yaml         every text
lib/features/<feature>/    annotated commands, data sources, custom fields
lib/gen/                   generated by `stx build`
```
